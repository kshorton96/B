# Connect private online submissions

No service account, endpoint, paid plan or live inbox has been created. Offline contribution packages work now. Online submission delivery is NOT activated or tested.

Recommended starting option: a Society-owned Tally Free form. Checked October 26, 2026: https://tally.so/pricing and https://tally.so/help/file-uploads describe unlimited forms/submissions within fair use and free file uploads up to 10 MB per file. Contributors can use the published public form without creating an account; the museum needs an owner account. Limits and terms may change. Free file upload is a better fit than Google Forms uploads requiring respondent sign-in. GitHub Issues require accounts and expose submissions publicly, so they are not the public route.

1. The Society creates and controls its own free account; enable available account security and keep recovery access with authorized officers. Do not purchase a plan.
2. Create a public form with the questions from contribute.html: kind, place, story, optional name/contact, multiple file uploads, and required review/contact consent. Include hidden fields named record and place to receive the linked record context. Include a separate optional media context if expanding this integration. The record hidden field currently includes the photograph reference when supplied.
3. Explain museum access, purpose, retention, external provider use, and how to request removal. Collect minimal contact details. Consent for review/contact is separate from public reproduction. Restrict file types and use the provider's available spam protection. Keep the inbox private.
4. Put the real published https://tally.so/r/FORMID URL in submissionFormUrl in contribution-config.json through a reviewed change. The website only accepts that HTTPS Tally host and form route. Do not put passwords or tokens in the file. The public page offers a link to the external form; it does not transfer locally entered text or selected files. Contributors enter their submission on Tally.
5. Test from a signed-out desktop browser and phone: record context, photograph context, multiple uploads, size rejection, required consent, confirmation and actual receipt in the private inbox. Test review and contact manually. Only then describe online delivery as working.
6. Review the provider's privacy terms and fair usage policy before launch. Download received files and metadata promptly into the museum's private backup system. Provider upload URLs can grant access to anyone holding the URL: do not expose them in public sheets, records or logs. Review retention and periodically remove files according to the museum policy. No archival storage guarantee is assumed.

Private review remains the documented register/inbox workflow. No public dashboard, multiuser draft storage, role authentication or direct publishing is implemented. Reassess service limits before high volume. The free alternative without a service account is the private downloadable contribution package delivered in person.
